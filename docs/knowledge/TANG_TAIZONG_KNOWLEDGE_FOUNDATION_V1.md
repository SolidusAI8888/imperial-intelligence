# Tang Taizong Knowledge Foundation V1.0

- 状态：Draft
- 日期：2026-08-16
- 对象：唐太宗李世民（Gold Standard Persona）
- 架构原则：History First

## 1. 目标

本文件定义唐太宗 Gold Standard 的第一版史料底座。目标不是先主观编写“唐太宗有哪些经验”，而是建立一套可追溯的权威资料层，随后从资料中抽取事件、经验、人物关系、决策过程、结果与反思。

系统必须遵循：

```text
权威史料
→ 原文片段
→ 历史主张
→ 事件
→ 可迁移经验
→ 人物经验画像
→ 问题匹配
→ 由相关人物回答
```

## 2. V1 核心史料

### A. 《旧唐书》

用途：唐代正史基础来源之一，重点覆盖太宗本纪、相关列传及制度背景。

V1 优先范围：

- 太宗本纪
- 魏征、房玄龄、杜如晦、长孙无忌、李靖、李勣等重要人物列传
- 与太子承乾、李泰、李治及皇室关系相关材料
- 与突厥、高句丽等重大决策相关材料

### B. 《新唐书》

用途：与《旧唐书》互证，并用于发现叙事差异、后世史家重构和争议点。

V1 原则：不得因为两书都属于正史就视为“两个独立事实来源”；同源材料需要标记可能的文本继承关系。

### C. 《资治通鉴》

用途：按时间线复原决策环境、前因后果及人物互动，尤其适合构建事件链和决策序列。

V1 原则：将《通鉴》的叙事与唐代更接近的一手或早期材料区分开，不把司马光的编纂判断直接当成唐太宗本人当时的认知。

### D. 《贞观政要》

用途：高价值的君臣对话、政策讨论、纳谏、任贤、政体与自我反思材料。

该书本身即以太宗时期政治言论与事迹为核心编纂对象，现存目录包含“君道、政体、任贤、求谏、纳谏、君臣鉴戒、择官”等主题，因此对 Experience Layer 特别重要。

V1 原则：

- 区分明确引语、叙事性转述和编者总结；
- 不将后世整理后的语句自动等同于逐字实录；
- 关键第一人称表达需与其他史料交叉核验。

## 3. 证据分层

### Tier A：核心历史依据

优先用于建立“发生过什么”。包括：

- 正史本纪与列传；
- 与事件时代接近、来源较清楚的史料；
- 可由多个来源相互印证的事实。

### Tier B：高价值解释材料

用于复原决策逻辑、人物关系和反思，但须注明编纂距离与作者立场。例如《资治通鉴》《贞观政要》中部分材料。

### Tier C：现代研究

用于处理：

- 史料来源学；
- 文本差异；
- 年代考证；
- 争议解释；
- 制度背景。

现代研究不能替代原始史料成为人格第一人称发言的唯一依据。

### Tier D：传说、通俗叙事与未经核验网络材料

不得作为核心 Experience 的直接依据。可以作为线索，但必须回溯至更可靠来源后才能进入知识库。

## 4. Knowledge Layer 最小数据单元

### Source

记录作品本身：书名、作者/编者、时代、版本、来源类别、数字化版本、可靠性说明。

### Passage

保存可定位到具体卷、篇、章节的原文片段或合法引用指针。

### Claim

从 Passage 中抽取的单一历史主张，例如：

> 贞观六年，魏征反对封禅，理由之一是隋末大乱后户口未复、仓廪尚虚。

Claim 必须区分：

- fact：事实主张
- attributed_statement：归属于具体人物的言论
- compiler_interpretation：编者判断
- modern_inference：现代研究推断

### Event

将多个 Claim 组织成事件，明确时间、参与者、背景、选择、行动、结果和争议。

### Experience

只有当 Event 有足够证据且具备可迁移价值时，才进入 Experience Layer。

## 5. 第一人称规则

唐太宗未来可以说“我当时……”，但系统必须知道这句话属于哪一级：

1. 史料明确记录其言论；
2. 多项行动证据支持的谨慎推断；
3. 后世史家的解释；
4. 现代系统为帮助用户理解所做的迁移性表达。

第 2—4 类不得伪装成逐字史实。

## 6. 史料冲突处理

出现冲突时不得静默选择一个版本。必须记录：

- 来源 A 的说法；
- 来源 B 的说法；
- 是否存在文本继承关系；
- 当前采用的工作结论；
- 置信度；
- 为什么暂时采用该结论。

若无法判断，则 Experience 必须显式保留不确定性。

## 7. 唐太宗 Gold Standard 的抽取顺序

V1 采用“资料驱动而非主题先验”的流程：

1. 建立核心史料索引；
2. 按时间与人物抽取重大事件候选；
3. 对事件建立 Passage → Claim → Event 证据链；
4. 从事件中抽取可迁移 Experience；
5. 对 Experience 聚类，形成唐太宗真实的 Experience Profile；
6. 再用于用户问题匹配与 Persona Recommendation。

因此，系统不预先规定唐太宗只有“识人、纳谏、战略”等若干类经验。分类应由完成一定规模的史料抽取后逐渐形成。

## 8. V1 完成标准

唐太宗 Knowledge Foundation V1 完成至少意味着：

- 核心四类史料完成来源登记；
- 每个来源有可靠性、用途和限制说明；
- Passage、Claim、Event、Experience 之间有统一 ID 规则；
- 任何 Gold Standard Experience 都能回溯到具体来源；
- 系统能够区分史实、人物原话、编者解释和现代推断；
- 不再允许从“唐太宗性格印象”直接生成未经史料支撑的现代建议。

## 9. 当前里程碑边界

本阶段不追求一次性全文导入所有唐代史籍，也不追求建立完整中国历史数据库。

当前任务只做足够支撑：

- 唐太宗 Gold Standard；
- History First 数据链路验证；
- 帝王智库 V1 的推荐与回答流程；
- 首期自媒体内容生产。

后续再将同一数据标准扩展至整个帝王系列及其他人物系列。
