# ADR-002：采用 History First 架构

- 状态：Accepted
- 日期：2026-08-15
- 项目：Historical Persona OS / 帝王智库 Imperial Intelligence

## 1. 背景

项目早期以 Persona 为中心组织数据，即先建立唐太宗等人物包，再从人物包中抽取经验并生成回答。随着产品目标逐步明确，这种方式暴露出一个根本问题：系统真正需要寻找的不是“哪个人物最适合回答”，而是“历史上哪些可验证经历与用户当前问题最相关”。

权威史书、原始史料、传记、奏疏、书信、考古材料及高可信现代研究，本身就是系统最重要的原始知识库。人物、经验和回答都应从这些资料中派生，而不应成为彼此隔离的数据孤岛。

## 2. 决策

Historical Persona OS 正式采用 **History First（历史优先）** 架构。

核心数据流调整为：

```text
权威历史资料
    ↓
Knowledge Layer
    ↓
事件、人物、关系、时间、地点、原文与出处
    ↓
Experience Layer
    ↓
问题分析与经验匹配
    ↓
选择最相关的人物
    ↓
Persona Layer
    ↓
Consultation Layer
    ↓
参考意见与启发
    ↓
用户自行决定
```

系统的第一搜索目标不是人物，而是相关且可信的历史经验。

## 3. 四层核心架构

### 3.1 Knowledge Layer

这是唯一的事实源头，负责保存和维护：

- 权威史书与原始史料；
- 原文片段及标准化出处；
- 人物；
- 历史事件；
- 人物关系；
- 时间与地点；
- 言论、诏令、奏疏、书信等可归属文本；
- 考古证据；
- 现代研究与争议观点；
- 证据等级、审核状态与版本。

Knowledge Layer 不直接提供现代建议。

### 3.2 Experience Layer

从 Knowledge Layer 中抽取和组织可迁移的人生经验，包括：

- 当时面临的问题；
- 可验证的选择空间；
- 可支持的思考与判断；
- 实际行动；
- 结果与代价；
- 后续反思；
- 可迁移原则；
- 不可迁移部分；
- 支持证据、反证与置信度。

Experience Layer 不允许脱离史料自由创造经历。

### 3.3 Persona Layer

Persona 不是原始数据库，而是由人物相关证据与经验组织形成的表达和认知运行层。

包括：

- 人生阶段；
- 世界观；
- 价值排序；
- 决策倾向；
- 稳定人格特征；
- 语言风格；
- 知识边界；
- 第一人称表达约束。

历史人物是相关历史经验的第一人称表达者，而不是事实来源本身。

### 3.4 Consultation Layer

负责：

1. 接收用户问题；
2. 分析问题结构；
3. 检索相关历史经验；
4. 对候选经验进行相关性、证据质量和可迁移性排序；
5. 根据高质量匹配经验选择最合适的人物；
6. 由该人物基于其真实人生经验进行第一人称回顾；
7. 将历史经验谨慎迁移到现代语境；
8. 提供参考意见和启发；
9. 明确最终决定权属于用户。

## 4. 人物选择原则

旧原则：

```text
问题 → 选择人物 → 找人物经历 → 回答
```

新原则：

```text
问题 → 找相关历史经验 → 评估经验质量 → 确认经验所属人物 → 推荐人物 → 回答
```

因此，人物推荐必须能够说明：

- 匹配到了哪些历史经历；
- 为什么这些经历与用户问题相关；
- 证据质量如何；
- 哪些差异限制了经验迁移。

## 5. 数据治理原则

- 人物不是原始事实源；
- Persona 结论必须可追溯至 Knowledge Layer；
- Experience 必须可追溯至具体事件与证据；
- 同一事件可以产生多个 Experience；
- 同一问题可以匹配多个人物的不同经历；
- 若没有足够相关的历史经验，系统必须明确承认，而不是为了回答而强行匹配；
- 历史资料库允许不断扩充，Persona 和 Experience 应可重新计算或重新审核。

## 6. 对现有工程的影响

现有 Persona Runtime、Consultation Contract、Experience Package 和 Evidence 设计继续保留，但其角色重新定义：

- Evidence / Knowledge 成为底层事实源；
- Experience 从底层史料派生；
- Persona 从人物证据与 Experience 派生；
- Consultation 消费 Experience 与 Persona，而不是直接从人物 YAML 自由生成答案。

未来目录与存储实现应逐步向这一数据流迁移，但本 ADR 不要求一次性重构全部代码。

## 7. 第一阶段实施策略

在不改变“下周完成帝王智库 V1 并产出首期视频”的里程碑前提下：

1. 继续把唐太宗作为 Gold Standard，验证 History First 数据链；
2. 优先建立唐太宗相关权威史料索引与事件结构；
3. 从史料与事件中抽取 Experience；
4. 用真实问题验证“问题 → Experience → Persona → Consultation”完整链路；
5. 其他帝王先满足推荐所需的最小数据标准，后续持续加深。

## 8. 长期扩展

该架构不限定于帝王。未来企业家、思想家、科学家、教育家等人物的可信资料，也统一进入 Knowledge Layer，再由相同方法生成 Experience、Persona 与 Consultation。

## 9. 核心结论

> Historical Persona OS 的核心不是“模拟名人”，而是从可靠的人类资料中检索、组织和迁移人生经验；人物是这些经验最自然、最可信的表达者。
