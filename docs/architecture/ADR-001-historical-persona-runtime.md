# ADR-001：采用历史人格运行时架构

- 状态：已接受
- 日期：2026-07-26
- 项目：帝王智库 Imperial Intelligence

## 背景

帝王智库的长期目标是支持中国正史记载的历代帝王，并通过文字、语音和半身互动数字人，为用户提供基于历史人格与人生经验的智能咨询。

系统不能把每位帝王分别开发成一个聊天机器人，也不能仅依赖“扮演某历史人物”的提示词。

## 决策

项目采用“历史人格运行时”架构。

每位帝王被实现为标准化 Persona Package。统一的 Persona Runtime 负责加载、验证和运行不同帝王人格。

FastAPI、手机网页、PWA、原生 App 和数字人客户端均属于外围应用或接口层，不包含核心人格逻辑。

## 核心运行流程

用户问题
→ 会话上下文
→ 帝王人格加载
→ 人生阶段加载
→ 历史记忆与证据检索
→ 人格化决策推理
→ 现代伦理与适用性校正
→ 语言表达
→ 数字人行为指令
→ 客户端展示

## 核心模块

### Persona Runtime

负责：

- 加载帝王人格数据包
- 选择帝王人生阶段
- 创建人格运行实例
- 管理人格状态
- 保证不同回答之间的人格一致性

### Historical Memory Engine

负责：

- 管理历史事件
- 管理人物关系
- 提取与当前问题相关的人生经验
- 区分人物当时已知和未知的历史信息

### Evidence Engine

负责：

- 管理史料来源
- 管理原文与现代研究
- 区分事实、解释和人格推断
- 提供支持证据、反证和置信度

### Reasoning Engine

负责：

- 识别用户问题类型
- 激活相关人格参数
- 执行帝王决策规则
- 生成候选建议和推理过程

### Dialogue Engine

负责：

- 判断是否需要追问
- 管理倾听、思考、回答和复盘阶段
- 维护咨询上下文
- 生成适合用户理解的表达

### Avatar Engine

负责：

- 输出人物表情
- 输出身体动作
- 输出视线和姿态
- 输出说话节奏和情绪状态
- 驱动半身互动数字人

## 数据与程序的关系

程序实现统一运行机制。

帝王之间的差异主要由数据包表达，包括：

- 人格参数
- 世界观
- 决策规则
- 历史事件
- 人物关系
- 语言风格
- 情绪触发
- 数字人行为参数
- 史料证据

新增帝王原则上不应要求修改核心代码。

## 当前实施策略

第一位标准样本为唐太宗李世民，默认人格阶段为贞观十五年。

唐太宗样本同时用于：

1. 验证产品价值；
2. 验证人格建模方法；
3. 验证工程架构的可复制性。

第二位验证样本应选择与唐太宗差异明显的帝王，以检验架构是否过度针对单一人物。

## 后果

### 优点

- 支持大量帝王快速扩展
- 核心逻辑可独立测试
- 手机端和数字人技术可以替换
- 历史资料与大模型供应商可以替换
- 人格系统不会被 FastAPI 或某个前端框架绑定

### 代价

- 初期架构工作较多
- 必须建立严格的数据规范
- 史料和人格结论需要审核
- 不适合用简单提示词快速堆砌大量人物

## 不采用的方案

### 每位帝王独立编写聊天机器人

会产生大量重复代码，难以保持质量一致。

### 只使用大模型系统提示词

人格容易漂移，历史事实难以审计，也无法稳定驱动数字人行为。

### 把所有逻辑写在 FastAPI 路由中

核心逻辑将与接口层耦合，未来难以支持手机端、语音端和多角色会议。
