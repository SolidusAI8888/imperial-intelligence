# History First Principle V1.0

- 状态：Accepted
- 日期：2026-08-15
- 平台：Historical Persona OS

## 1. 核心原则

Historical Persona OS 采用 **History First（历史优先）** 原则。

系统首先寻找与用户问题最相关、最可信、最可迁移的历史经验，然后再确定由谁来回答。

> 不是先选一个人物，再让他去“解释”用户问题；而是先从历史中找到最相关的经验，再由拥有这些经验的人，以其自身身份、人生经历和表达方式进行回答。

## 2. 数据源优先级

平台的事实与证据源来自：

- 权威史书；
- 原始文献；
- 奏疏、诏令、书信、日记、演讲、访谈等可归属资料；
- 考古材料；
- 高质量传记与学术研究；
- 对争议问题的多方研究与反证。

Persona、Experience 和 Consultation 都是这些资料经过结构化、审核和运行后产生的上层对象。

## 3. 人物不是数据源

唐太宗、刘邦、朱元璋、乔布斯、巴菲特等人物，不应被视为一个预先封闭的“答案数据库”。

人物的可用回答能力必须来自：

```text
可靠资料
→ 历史/人生事件
→ 可验证经验
→ 人格与人生阶段模型
→ 当前问题中的第一人称表达
```

因此，人物不能声称自己拥有史料无法支持的经历、想法或结论。

## 4. 经验优先于人物推荐

对于未指定回答者的问题，系统推荐逻辑为：

```text
用户问题
→ 分析问题结构
→ 检索相关人生经历
→ 评估相关性
→ 评估证据质量
→ 评估可迁移性
→ 得到候选 Experience
→ 聚合 Experience 所属人物
→ 推荐最合适回答者
```

推荐理由必须可解释。

## 5. 第一人称回答规则

人物回答应优先采用以下顺序：

1. 我曾经遇到过哪些可比的事情；
2. 当时发生了什么；
3. 我当时如何考虑——仅在证据足够时陈述；
4. 我采取了什么行动；
5. 结果和代价是什么；
6. 我从中可以提炼出什么经验；
7. 你的情况与我当年的情况有哪些相同与不同；
8. 如果我是你，我会如何考虑或行动；
9. 最终决定由你自己作出。

若无足够相似经验，必须明确说明，不得伪造先例。

## 6. 为什么现代人可以参考古人的意见

平台不假设古人理解现代技术、法律或社会制度。

可迁移的是：

- 人性冲突；
- 信任与背叛；
- 风险与收益；
- 责任与自由；
- 选择与放弃；
- 权力与合作；
- 失败与重新开始；
- 长短期权衡；
- 判断与行动逻辑。

不可直接迁移的是古代制度、身份特权、暴力手段以及不符合现代法律伦理的具体做法。

## 7. 平台最终目的

平台不是为用户提供“历史权威答案”。

它的目标是：

> 基于人类已有的可靠人生记录，为用户提供相关经验、不同视角和思考启发，让用户结合自己的现实条件形成自己的决定。

## 8. 产品检验问题

任何新功能都应回答：

- 它是否让事实更靠近原始资料？
- 它是否让 Experience 更可追溯？
- 它是否让人物推荐更有依据？
- 它是否减少了为了“像某个人”而自由编造的空间？
- 它是否帮助用户思考，而不是替用户做决定？

若答案是否定的，该功能不应优先进入核心产品。
